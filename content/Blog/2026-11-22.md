Probably like many, I've been on a bit of a rollercoaster ride with AI-assisted (vibe) coding recently. I was suddenly amazed by what it could do some time last year, then have used it with mixed results in a number of projects since then, seeing it confidently do things wrong or in an over-complicated way, forget key instructions, or seemingly be completely unable to do certain things correctly, which has undermined my trust in using it. So when I thought about using it for a recent project it was still with a sense of experimentation. 

I need to customise SENAITE LIMS and would like to use the add-on framework they provide ([senaite.starter](https://github.com/senaite/senaite.starter)) rather than my previous more hacky approach. I still don't feel like I understand the workings of SENAITE (and its underlying technologies Plone and Zope) enough to do this myself, though I am getting there slowly. At the moment I have GitHub Copilot at work so decided to try that. 

Initial results were disappointing. Based on a prompt describing the desired changes (basically modifications of core data sets and forms) it only managed to partly complete this, and introduced various bugs along the way. This tediously took up the whole usable part of one working day, as I had to repeatedly pull changes to the server, rebuild the app and then reinstall the add-on within the Web interface. I was starting to think that this was too obscure a task for LLMs built on more mainstream and better documented technologies. 

The next day I checked which model GH Pilot was using, and realised it was set to the default option (it had somehow reset since I last used it months ago). I changed it to Claude Sonnet 5.5, on the "max" settings. In my initial prompt I specified the desired end-results, and also specified the approach I took previously to change things (involving a lot of reading/grepping through the codebase). This time it did a full review of the [senaite.patient](https://github.com/senaite/senaite.patient) codebase and proposed a plan. After some back and forward on that plan, and some further modifications, it made the changes [here](https://github.com/prcleary/senaite.starter/compare/master...add-cnic-field). This has made all the changes I needed, plus has added some functionality that I had not dreamed of being able to add, which will make SENAITE easier to use. As far as I can test it on an instance that hasn't been populated with much metadata yet, it all works very well. 

Unfortunately I have used my entire quota of tokens in two days (renewing December 1st), but it has probably saved me weeks of work. As I have learned previously (and will no doubt learn again), use the most expensive model you have access to (especially if you are not paying), give lengthy explicit instructions and develop a plan before you change any code.

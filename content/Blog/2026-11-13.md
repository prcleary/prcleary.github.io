I am getting back into the weeds with [SENAITE](https://www.senaite.com/). After a pilot of it in one lab (with much learning), we are planning to implement it for a small group of public health laboratories. I am likely to be even busier with new other responsibilities from now on and so I need a more streamlined approach to deployment. 

I want to use the SENAITE API as much as I can to set things up, rather than doing everything manually. Earlier this year I made a start on an R package for interacting with the SENAITE API and I intend to develop this further: [prcleary/sen8r: Convenient R interface for interacting with the SENAITE LIMS API](https://github.com/prcleary/sen8r). My previous approach to implementation was (1) try to understand as much as possible and do it myself, and failing that (2) use trial and error. I now have access to GitHub Copilot (I think) so I am wondering if this can help me when I am resorting to option 2. 

My plan is to develop the R package by testing it against a local instance of SENAITE. I can easily set up VMs on [Proxmox](https://www.proxmox.com/en/), the virtualisation environment running on my home server. Proxmox allows you to set up a VM just the way you like it and then make that into a template from which you can clone throwaway instances. This means I can thoroughly break a SENAITE instance while testing and simply start afresh on a new one; much better than trying things on a working instance...

I am probably going to have to make changes to the codebase of SENAITE add-on packages (I haven't dared to meddle with the core codebase yet) to e.g. add new data collection fields for national identity card number, add in some hardcoded geographies, add new lab report templates, etc etc, so I need to allow for that. I know that you can create your own add-on package and that that would more maintainable, but I haven't been confident enough to try that yet and am also not entirely clear that all the tweaks I would want to make would be feasible with an add-on package. Because of the need for customisation, I won't be able to use convenient Docker-based approaches to installing SENAITE such as [🐳 Ingwe Bika LIMS 4 ](https://github.com/bikalims/bika.lims), which looks very good. 

I also need to make sure I am using the correct versions of the different SENAITE add-on packages. The latest release of SENAITE is version 2.6.0. I worked previously on version 2.5.0. Though the minor version number increment would seem to suggest backwardly compatible changes, in reality there are fundamental changes afoot which could make earlier versions of add-on packages incompatible. This is because SENAITE currently still has to use an outdated version of Python; 2.6.0 is a stepping stone on the way to compatibility of SENAITE with Python 3, with changes to some underlying data types. I was initially planning to stick to version 2.5.0 of SENAITE but after some experimentation it seems that the latest releases of the bare minimum add-on packages I need are compatible with [senaite.starter](https://github.com/senaite/senaite.starter), which sets up SENAITE version 2.6.0 by default. The add-ons I need are: 

- [senaite/senaite.patient: Patient handling for SENAITE](https://github.com/senaite/senaite.patient) (1.5.0) - add fields/forms for patient data
- [senaite/senaite.diagnosis: Diseases, Signs and Symptoms and Etiologic agents handling for SENAITE](https://github.com/senaite/senaite.diagnosis) (1.1.0) - add fields/forms for capturing other diagnostic data
- [senaite/senaite.ast: Antibiotic Sensitivity Testing (AST) for SENAITE](https://github.com/senaite/senaite.ast) (1.2.0) - add fields/forms for AMR data
- [senaite/senaite.microorganism: Microorganisms handling for SENAITE](https://github.com/senaite/senaite.microorganism) (1.2.0) - adds some lists of microorganisms for the AST add-on (which didn't work for me previously when I tried it, as in it didn't create the lists of microorganisms)
- [senaite/senaite.abx: Antibiotics handling for SENAITE](https://github.com/senaite/senaite.abx) (1.3.0) - adds some lists of antibiotics for the AST add-on

These are the same add-ons used by [Bika Health](https://www.bikalims.org/new-manual/bika-health) interestingly.

The following steps are those needed to create my template.

- Create a new Ubuntu 24 VM.
- Update it and install various dependencies.
- Create a user with the appropriate permissions and switch to being that user for the remainder of the process. 
- Set up [pyenv](https://github.com/pyenv/pyenv) and create a virtual environment for the appropriate (old) version of Python.
- Clone the `senaite.starter` repo.
- Fork the `senaite.patient` and `senaite.impress` repos, create branches off the tags for the appropriate releases, then clone those into the `src/` folder of `senaite.starter`. Note that you can only have one fork per repo in one user account, so you will need different branches if you are using your fork for different deployments.
- Configure and build SENAITE.
- Do some testing.

Thanks to [Proxmox Community Scripts](https://community-scripts.org/), all I need to do to create a new Ubuntu 24 VM is: 

```bash
var_cpu="4" var_ram="2048" var_disk="8" bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/ubuntu.sh)"
```

Note that this specifies things like number of CPUs, available RAM and disk size. Start the container and note its IP address.

From the console for the container, install dependencies:

```bash
apt update; apt upgrade -y
apt install build-essential bzip2 fontconfig git icu-devtools libbz2-1.0 libbz2-dev libcairo2 libdatrie1 libexpat1-dev libffi-dev libgdbm-compat-dev libgdbm-dev libgdk-pixbuf-2.0-0 libgdk-pixbuf-xlib-2.0-0 libgdk-pixbuf2.0-bin libgdk-pixbuf2.0-common libgraphite2-3 libharfbuzz0b libicu-dev libjpeg-dev libjpeg-turbo8-dev liblzma-dev libncursesw5-dev libnss3-dev libopenjp2-7-dev libpango-1.0-0 libpangocairo-1.0-0 libpangoft2-1.0-0 libpcre3 libpcre3-dev libpixman-1-0 libreadline-dev libsqlite3-dev libssl-dev libthai-data libthai0 libtiff5-dev libxcb-render0 libxcb-shm0 libxrender1 shared-mime-info uuid-dev vim zlib1g-dev
```

Create a user and become that user:

```bash
useradd -m -G sudo -s /bin/bash senaite
passwd senaite  # enter a new password twice
su - senaite
```

Set up the `pyenv` virtual environment: 

```bash
curl https://pyenv.run | bash
export PYENV_ROOT="$HOME/.pyenv"
[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init - bash)"
# also add last three lines above that to .bashrc then
exec "$SHELL"
pyenv doctor  # you want: Congratulations! You are ready to build pythons!
pyenv install 2.7.18
pyenv versions  # to check that version is installed
pyenv virtualenv 2.7.18 python2.7-senaite
pyenv activate python2.7-senaite
python  # to check you get Python 2.7.18; `exit()` to exit
```

Clone repos, including your forked repos (note placeholders beginning "your...") and create branches for your own changes. I did this on my work computer as I only want my instance to be able to pull from GitHub. After pushing this to GitHub I pulled the changes to the instance and checked out the development branches.

```bash
cd
git clone https://github.com/senaite/senaite.starter.git
cd senaite.starter/src
git clone https://github.com/yourusername/senaite.patient.yourfork.git
git clone https://github.com/yourusername/senaite.impress.yourfork.git
cd senaite.patient.yourfork
git checkout master
git remote add upstream https://github.com/senaite/senaite.patient.git
git fetch upstream --tags
git switch --no-track -c yourbranch v1.5.0
git push -u origin yourbranch
cd ../senaite.impress.yourfork
git checkout 2.x
git remote add upstream https://github.com/senaite/senaite.impress.git
git fetch upstream --tags
git switch --no-track -c yourbranch 2.6.0
git push -u origin yourbranch
```

Configure the SENAITE build via the `buildout.cfg` file.

```bash
cd ..
cp -i buildout.cfg buildout.cfg.bak
vim buildout.cfg
```

The main changes of interest are for add-ons, including my (to be tweaked) versions.

```
...
eggs =
    senaite.lims
    senaite.patient
    senaite.microorganism
    senaite.abx
    senaite.ast
    senaite.diagnosis

develop = .
    src/senaite.patient.yourfork

```

Make sure to change the admin password too. You may notice that  `et-xmlfile` is pinned to both 1.1.0 and <2.0.0 versions but ignore that as it doesn't seem to cause any problems.

Now you can build SENAITE.

```bash
pip install -r requirements.txt
buildout -c buildout.cfg
```

You should see the usual long terrifying output as you bite your nails, but it should complete. All being well you can now run SENAITE for testing purposes with:

```bash
bin/instance fg
```

You should be able to open SENAITE in your browser using the IP address you noted earlier and adding the port 8080, i.e. something like `http://192.168.1.134:8080/`. 

Through the web interface, create a new SENAITE site, leaving everything at defaults as much as possible - use the admin password you set earlier. Within the new SENAITE site, look for the little menu top right and click "Site Setup". Go into "Add-ons" and install all the add-ons offered (note that add-ons will later need to be reinstalled if you tweak them).

Using the Proxmox GUI tools, shutdown the instance, back it up (preferably "protected") and then create a template from it. You can rename it if you like from the Proxmox host shell with e.g.

```bash
pct set xxx --hostname senaite-starter-template
```

Now you can use the GUI tools to create a "linked clone" of the template and test it all works. Delete that clone and then create another one for testing what you can do with the API - that is where I am up to.
